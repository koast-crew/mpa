# Spring Security 동적 ROLE 인증 분석

## 개요

이 프로젝트는 Spring Security의 ROLE을 코드에 하드코딩하지 않고, **DB에서 관리하며 사용자 그룹에 동적으로 할당**하는 구조다.  
사용자 → 사용자 그룹 → 그룹에 할당된 ROLE → Spring Security GrantedAuthority 흐름으로 권한을 부여한다.

---

## 전체 인증 흐름

```
클라이언트
  POST /login/process
  Content-Type: application/json
  Body: { "username": "...", "password": "..." }
       │
       ▼
JsonUsernamePasswordAuthenticationFilter   [security/filter/]
  - JSON body 파싱
  - UsernamePasswordAuthenticationToken 생성
  - AuthenticationManager.authenticate() 호출
       │
       ▼
AuthenticationManager
  - 등록된 AuthenticationProvider 순회
       │
       ▼
CustomAuthenticationProvider               [security/]
  - UserService.findByUserIdAndPolicy()    → DB: user_info (로그인 사용자 조회)
  - BCryptPasswordEncoder.matches()        → 비밀번호 검증
  - PolicyService.getLatest()              → DB: policy (비밀번호 만료, 잠금, 실패 횟수 정책)
  - 세션에 UserSession 저장
  - 인증 성공 시 UsernamePasswordAuthenticationToken 반환
       │
       ├── 성공 ──▶ CustomAuthenticationSuccessHandler  [security/handler/]
       │              - 세션에 UserPrincipal 저장
       │              - HTTP 200 + ApiResponse JSON 응답
       │
       └── 실패 ──▶ CustomAuthenticationFailureHandler  [security/handler/]
                     - HTTP 401 + ApiResponse(BusinessException) JSON 응답

인증 없이 보호된 URL 접근:
  → CustomAuthenticationEntryPoint  [security/exception/]  → HTTP 401

인증은 됐으나 권한 없음:
  → CustomAccessDeniedHandler       [security/exception/]  → HTTP 403
```

## 동적 ROLE 핵심 구조

### DB 테이블 관계

```
user_info ──(N:1)──▶ user_group ──(N:M, user_group_role)──▶ role
```

| 테이블 | 핵심 컬럼 | 역할 |
|--------|-----------|------|
| `user_info` | `user_id`, `user_group_id`, `password`, `status`, ... | 사용자 정보 |
| `user_group` | `user_group_id`, `user_group_name` | 사용자 그룹 |
| `user_group_role` | `user_group_id`, `role_id` | 그룹-ROLE N:M 연결 |
| `role` | `role_id`, `role_name`, `role_key`, `role_target`, `role_type` | ROLE 정보 |
| `policy` | `password_change_term`, `user_fail_login_count`, `security_session_timeout`, ... | 로그인 정책 |

### 동적 ROLE 변환 경로

```
DB role.role_name ("ADMIN_LOGIN")
    ↓
UserGroup.roles (List<Role>)
    ↓
CustomUserDetails.getAuthorities()
    → role.getRoleName() → new SimpleGrantedAuthority("ADMIN_LOGIN")
    ↓
Spring Security GrantedAuthority 체크
    ← SecurityConfig: .hasAuthority(RoleKey.ADMIN_LOGIN.name())
```

### RoleKey enum — DB role_name과 1:1 매핑 필수

```java
// koast.admin.domain.role.RoleKey
public enum RoleKey {
    ADMIN_LOGIN,          // 관리자 페이지 로그인
    ADMIN_USER_MANAGE,    // 사용자 관리
    ADMIN_LAYER_MANAGE,   // 레이어 관리
    USER_LOGIN,           // 사용자 페이지 로그인
    USER_DATA_CREATE,     // 데이터 등록
    USER_DATA_READ        // 데이터 조회
}
```

> **주의**: DB `role` 테이블의 `role_name` 값이 `RoleKey.name()`과 **대소문자까지 정확히 일치**해야 한다.

## 클래스별 상세 분석

### 1. SecurityConfig — 필터 체인 설정

**파일**: `config/SecurityConfig.java`

```java

JsonUsernamePasswordAuthenticationFilter jsonFilter = new JsonUsernamePasswordAuthenticationFilter(objectMapper);
jsonFilter.setFilterProcessesUrl("/login/process");  // 로그인 엔드포인트

// 권한 규칙
.authorizeHttpRequests(auth -> auth
    .requestMatchers("/login/**", "/css/**", "/js/**", "/images/**").permitAll()
    .anyRequest().hasAuthority(RoleKey.ADMIN_LOGIN.name())  // ADMIN_LOGIN 권한 필수

// 세션: 동시 접속 1명 제한
.sessionManagement(session -> session.maximumSessions(1))

// CSRF 비활성화 (REST API + 세션 인증 혼합 구조)
.csrf(csrf -> csrf.disable())
```

### 2. JsonUsernamePasswordAuthenticationFilter — JSON 로그인 필터

**파일**: `security/filter/JsonUsernamePasswordAuthenticationFilter.java`

Spring Security 기본 필터는 `application/x-www-form-urlencoded` 형식만 처리한다.  
이 필터는 `application/json` body를 파싱해 동일한 인증 흐름으로 연결한다.

```java
// Content-Type 검사
if (!request.getContentType().startsWith("application/json")) {
    throw new IllegalArgumentException("Only application/json is supported");
}

// JSON 파싱 후 인증 토큰 생성
Map<String, String> loginRequest = objectMapper.readValue(request.getInputStream(), Map.class);
UsernamePasswordAuthenticationToken authRequest =
    new UsernamePasswordAuthenticationToken(username, password);

return this.getAuthenticationManager().authenticate(authRequest);
```

### 3. CustomAuthenticationProvider — 실제 인증 로직

**파일**: `security/CustomAuthenticationProvider.java`

인증의 핵심. Spring Security 기본 DaoAuthenticationProvider를 대체한다.

처리 순서:
1. `PolicyService.getLatest()` — 현재 적용 중인 정책 조회
2. `UserService.findByUserIdAndPolicy()` — 사용자 정보 + 정책 계산값 조회
3. `BCryptPasswordEncoder.matches()` — 비밀번호 검증
4. 계정 상태 검사 (ACTIVE/TEMP_PASSWORD만 통과)
5. 실패 횟수 / 마지막 로그인 잠금 검사
6. 성공 시 실패 횟수 초기화, 세션에 UserSession 저장

```java
// 현재 반환값 — 비어있는 authorities!
return new UsernamePasswordAuthenticationToken(userId, null, List.of());
```

### 4. CustomUserDetailsService — 사용자 로드 서비스

**파일**: `security/CustomUserDetailsService.java`

`UserDetailsService` 구현체. 사용자 ID로 `User` 엔티티(그룹+롤 포함)를 로드한다.

```java
public UserDetails loadUserByUsername(String userId) throws UsernameNotFoundException {
    User user = userRepository.findUserWithGroupAndRoles(userId)
            .orElseThrow(() -> new UsernameNotFoundException("사용자를 찾을 수 없습니다: " + userId));
    return new CustomUserDetails(user);
}
```

> **현재 상태**: `CustomAuthenticationProvider`가 등록되어 있어 Spring Security가 이 서비스를 호출하지 않는다.  
> Provider가 직접 `UserService`를 통해 사용자를 조회하기 때문.

### 5. CustomUserDetails — UserDetails 구현체 (동적 ROLE 핵심)

**파일**: `security/CustomUserDetails.java`

```java
@Override
public Collection<? extends GrantedAuthority> getAuthorities() {
    return user.getUserGroup().getRoles().stream()
            .map(role -> new SimpleGrantedAuthority(role.getRoleName()))  // DB role_name → GrantedAuthority
            .collect(Collectors.toList());
}
```

이 `getAuthorities()`가 동적 ROLE의 핵심이다. DB에서 로드한 role_name을 그대로 `SimpleGrantedAuthority`로 변환한다.

> **현재 상태**: `CustomUserDetailsService`가 호출되지 않으므로, 이 클래스도 현재 인증 흐름에서는 사용되지 않는다.

### 6. UserPrincipal — 세션 저장 객체

**파일**: `security/UserPrincipal.java`

`UserDetails` + `Serializable` 구현체. 세션에 저장될 인증 사용자 정보를 담는다.

- `authorities` 필드로 GrantedAuthority 목록 보유
- `UserStatus` enum 기반 계정 상태 메서드 구현 (만료, 잠금, 비활성화 구분)
- `loginIp` 필드로 세션 하이재킹 체크 가능

```java
// 계정 상태별 정밀 구현
@Override public boolean isAccountNonExpired() {
    return !(status == UserStatus.EXPIRED || status == UserStatus.PENDING_APPROVAL || status == UserStatus.DORMANT);
}
@Override public boolean isAccountNonLocked() {
    return status != UserStatus.LOCKED || Boolean.TRUE.equals(lastLoginLockOver);
}
```

> **현재 상태**: SuccessHandler에서 사용하려 하지만, Provider가 UserPrincipal을 반환하지 않아 ClassCastException 발생.

## 발견된 버그

현재 코드는 **컴파일은 불가능하며, 가능하더라도 로그인이 정상 동작하지 않는다**.

---

### BUG-1 [Critical] BCryptPasswordEncoder 미주입 → NPE

**파일**: `security/CustomAuthenticationProvider.java:34`

```java
// 현재 — @Autowired 없음, @RequiredArgsConstructor 적용 안 됨 (final 아님)
private BCryptPasswordEncoder bCryptPasswordEncoder;

// 결과: bCryptPasswordEncoder.matches(...) 호출 시 NullPointerException
```

**수정**:

```java
// 방법 1: final + @RequiredArgsConstructor (기존 패턴과 일관)
private final BCryptPasswordEncoder bCryptPasswordEncoder;

// 방법 2: SecurityConfig에서 @Bean 등록 필요
@Bean
public BCryptPasswordEncoder passwordEncoder() {
    return new BCryptPasswordEncoder();
}
```

---

### BUG-2 [Critical] Provider가 빈 authorities 반환 → 모든 요청 권한 거부

**파일**: `security/CustomAuthenticationProvider.java:78`

```java
// 현재 — authorities가 비어있음
return new UsernamePasswordAuthenticationToken(userId, null, List.of());

// 결과: 로그인 성공 후 SecurityContext에는 권한 없는 토큰이 저장됨
//       SecurityConfig의 .hasAuthority(RoleKey.ADMIN_LOGIN.name()) 체크 → 모두 거부 (403)
```

**수정**: Provider가 DB에서 사용자의 ROLE을 로드해 authorities로 설정해야 한다.

```java
// CustomUserDetailsService를 Provider에서 호출
UserDetails userDetails = customUserDetailsService.loadUserByUsername(userId);
return new UsernamePasswordAuthenticationToken(userDetails, null, userDetails.getAuthorities());
```

---

### BUG-3 [Critical] SuccessHandler ClassCastException

**파일**: `security/handler/CustomAuthenticationSuccessHandler.java:34`

```java
// 현재 — Provider가 String userId를 principal로 반환하는데 UserPrincipal로 캐스팅
UserPrincipal userPrincipal = (UserPrincipal) authentication.getPrincipal();
// ClassCastException: String cannot be cast to UserPrincipal
```

**수정**: BUG-2 수정과 연동. Provider의 반환값을 `UserPrincipal`로 변경하면 해소된다.

```java
// Provider에서 UserPrincipal을 principal로 반환하도록 수정 후
UserPrincipal userPrincipal = (UserPrincipal) authentication.getPrincipal();  // 정상 동작
```

---

### BUG-4 [Critical] UserDetailsService 컴파일 에러

**파일**: `security/CustomUserDetailsService.java:26`  
**파일**: `repository/UserRepository.java:21`

```java
// CustomUserDetailsService — Optional<User> 기대
User user = userRepository.findUserWithGroupAndRoles(userId)
        .orElseThrow(...);  // ← Optional 메서드 호출

// UserRepository — Optional이 아닌 직접 반환
UserWithGroupAndRolesResponse findUserWithGroupAndRoles(String userId);
// 반환 타입도 UserWithGroupAndRolesResponse로 User와 다름
```

두 가지 불일치:
1. 반환 타입: `UserWithGroupAndRolesResponse` vs `User`
2. Optional 미사용: `.orElseThrow()` 호출 불가

**수정**: Repository와 Service를 일관된 타입으로 통일해야 한다.  
`CustomUserDetails`가 `User` 엔티티를 받으므로, Repository에서 `User` (with group+roles 조인)를 반환하도록 변경 권장.

```java
// UserRepository 수정
Optional<User> findUserWithGroupAndRoles(String userId);

// MyBatis XML에서 User → userGroup → roles 중첩 resultMap으로 매핑
```

---

### 개선-1 [Low] ObjectMapper 매 요청 생성

**파일**: `security/exception/CustomAuthenticationEntryPoint.java:33`  
**파일**: `security/exception/CustomAccessDeniedHandler.java:30`

```java
// 현재 — 요청마다 새 ObjectMapper 생성 (비효율)
response.getWriter().write(new ObjectMapper().writeValueAsString(apiResponse));
```

**수정**: `WebMvcConfig`에서 등록한 Bean 주입.

```java
@Component
@RequiredArgsConstructor
public class CustomAuthenticationEntryPoint implements AuthenticationEntryPoint {
    private final ObjectMapper objectMapper;  // Bean 주입
    ...
}
```

---

### 개선-2 [Medium] 세션 이중 저장

**파일**: `security/CustomAuthenticationProvider.java:63–71`  
**파일**: `security/handler/CustomAuthenticationSuccessHandler.java:37`

현재 Provider에서 `UserSession`을, SuccessHandler에서 `UserPrincipal`을 각각 `"USER_SESSION"` 키로 세션에 저장한다.  
동일 키에 다른 타입이 저장되는 구조 — BUG-2·3 수정 시 Provider의 세션 저장 로직을 제거하고 SuccessHandler에서 일원화해야 한다.

## 수정 방향 요약

BUG-1~4를 한 번에 해결하는 권장 수정 흐름:

```
1. SecurityConfig에 BCryptPasswordEncoder @Bean 등록

2. CustomUserDetailsService 수정
   - UserRepository.findUserWithGroupAndRoles() → Optional<User> 반환으로 변경
   - MyBatis XML: User → userGroup → roles 중첩 조인 쿼리 작성
   - loadUserByUsername()에서 UserPrincipal 빌드 후 반환

3. CustomAuthenticationProvider 수정
   - bCryptPasswordEncoder → final + 생성자 주입
   - authenticate() 내에서 customUserDetailsService.loadUserByUsername() 호출
   - 반환: new UsernamePasswordAuthenticationToken(userPrincipal, null, userPrincipal.getAuthorities())
   - Provider 내 세션 저장 로직 제거 (SuccessHandler로 일원화)

4. CustomAccessDeniedHandler, CustomAuthenticationEntryPoint
   - ObjectMapper 필드 주입으로 변경
```

수정 후 인증 흐름:

```
Filter → Manager → CustomAuthenticationProvider
    → customUserDetailsService.loadUserByUsername()   ← 이제 실제 사용
        → UserRepository (Optional<User> with group+roles)
        → CustomUserDetails.getAuthorities()           ← DB role_name → GrantedAuthority
        → UserPrincipal 빌드
    → BCryptPasswordEncoder.matches()
    → 정책 검사
    → UsernamePasswordAuthenticationToken(userPrincipal, null, userPrincipal.getAuthorities())
→ CustomAuthenticationSuccessHandler
    → (UserPrincipal) authentication.getPrincipal()    ← 정상 캐스팅
    → 세션 저장 + JSON 응답
```

## 다른 프로젝트 복제 가이드

### 필수 의존성

```groovy
implementation 'org.springframework.boot:spring-boot-starter-security'
```

### 1단계: DB 스키마

```sql
-- ROLE 테이블
CREATE TABLE role (
    role_id      SERIAL PRIMARY KEY,
    role_name    VARCHAR(100) NOT NULL UNIQUE,  -- RoleKey enum 값과 일치
    role_key     VARCHAR(100),
    role_target  VARCHAR(50),    -- USER, ADMIN
    role_type    VARCHAR(50),    -- USER, ADMIN, API
    basic        BOOLEAN DEFAULT false,
    available    BOOLEAN DEFAULT true,
    description  VARCHAR(500),
    created_date TIMESTAMP DEFAULT NOW()
);

-- 사용자 그룹 테이블
CREATE TABLE user_group (
    user_group_id   SERIAL PRIMARY KEY,
    user_group_name VARCHAR(200) NOT NULL,
    available       BOOLEAN DEFAULT true,
    ...
);

-- 그룹-ROLE N:M 연결 테이블
CREATE TABLE user_group_role (
    user_group_id INTEGER REFERENCES user_group(user_group_id),
    role_id       INTEGER REFERENCES role(role_id),
    PRIMARY KEY (user_group_id, role_id)
);

-- 사용자 테이블 (user_group과 연결)
CREATE TABLE user_info (
    user_id        VARCHAR(100) PRIMARY KEY,
    user_group_id  INTEGER REFERENCES user_group(user_group_id),
    password       VARCHAR(200) NOT NULL,  -- BCrypt 해시
    status         VARCHAR(50) DEFAULT 'ACTIVE',
    fail_login_count INTEGER DEFAULT 0,
    last_login_date  TIMESTAMP,
    ...
);
```

        <id     property="userGroupId"   column="user_group_id"/>

        <collection property="roles" ofType="koast.your.domain.role.entity.Role">

    </association>
</resultMap>

<select id="findUserWithGroupAndRoles" parameterType="String" resultMap="UserWithGroupAndRolesMap">
    SELECT
        u.user_id, u.user_name, u.password, u.status,
        ug.user_group_id, ug.user_group_name,
        r.role_id, r.role_name
    FROM user_info u
    LEFT JOIN user_group ug ON u.user_group_id = ug.user_group_id
    LEFT JOIN user_group_role ugr ON ug.user_group_id = ugr.user_group_id
    LEFT JOIN role r ON ugr.role_id = r.role_id
    WHERE u.user_id = #{userId}
</select>
