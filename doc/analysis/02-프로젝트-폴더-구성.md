- **대상**: `admin-api/src/main/java/koast/admin/`
- **상태**: 완료 (일부 후속 작업 예정)

---

## 아키텍처 방향

**레이어드 아키텍처 기반 + domain은 모델 전용으로 분리**

- `controller/`, `service/`, `repository/` — 레이어 기준
- `domain/` — Entity / DTO / Enum / MapStruct Mapper 만 위치 (비즈니스 로직 없음)
- `security/` — Spring Security 커스터마이징 전체를 독립 패키지로 격리
- `common/` — 비즈니스와 무관한 공통 코드
- `config/` — 설정 클래스 및 설정 관련 유틸

> **선택 이유**: 도메인 기준은 도메인마다 controller/service/repository 서브 패키지가 반복되어
> 규모 대비 폴더 구조가 복잡해진다. 레이어드는 팀 러닝커브가 낮고 이 프로젝트 규모에 적합하다.

## 후속 작업

### UserSession / UserWithGroupAndRolesResponse → UserPrincipal 통합

현재 `domain/user/` 아래 두 클래스가 `UserPrincipal`과 거의 동일한 필드를 가진 채 잔존.  
Security 버그 수정(Phase 4) 시 함께 처리 예정.

```
제거 대상:
  domain/user/session/UserSession.java
  domain/user/dto/UserWithGroupAndRolesResponse.java
```

### AppConfig 책임 분리

```
현재: AppConfig (DataSource + MyBatis + TransactionManager + ComponentScan)
목표:
  DataSourceConfig  → DataSource, TransactionManager
  MyBatisConfig     → SqlSessionFactory, SqlSessionTemplate, @MapperScan
```
